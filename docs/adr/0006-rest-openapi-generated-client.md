# ADR-0006: REST + OpenAPI, generated TypeScript client

- **Status:** Proposed
- **Date:** 2026-10-26

## Context
One known client (the Angular SPA) for now, but the API is also a showcase of API design. Hand-written TypeScript models drift from the backend.

## Decision
- Resource-oriented REST under `/api/v1/…`, JSON, RFC 9457 ProblemDetails for errors, `ETag`/`If-Match` for optimistic concurrency.
- The OpenAPI document is generated by ASP.NET Core (`Microsoft.AspNetCore.OpenApi`) and **committed** to the repo (`api/openapi.v1.json`). CI fails when it changes without being committed, which makes contract changes visible in PRs.
- The TypeScript client is generated from that file (e.g. orval or openapi-generator). It's never edited by hand.

## Alternatives considered
- **GraphQL:** a natural fit for the network graph, but it adds a second paradigm to learn and hides HTTP semantics. Could be added later for the world-view query.
- **gRPC:** no browser-native support. Overkill for this.

## Consequences
- Contract-first discipline. Breaking changes are visible in diffs.
- An extra build step in the frontend (`npm run generate:api`).
