# Primer: the terms used in this guide

Every technical term in the guide, in plain language: what it is, and where you'll meet it in this project. Read a section when a chapter mentions a term you don't know. You don't need to learn all of it up front.

## .NET basics

| Term | What it is | In this project |
|---|---|---|
| **.NET 10** | Microsoft's free, cross-platform platform for running C# programs. Version 10 is the current *LTS* (Long Term Support, 3 years of updates). | Everything in `src/` and `tests/` |
| **C# 14** | The language version that comes with .NET 10. | All backend code |
| **SDK** | The toolkit for building .NET: compiler plus the `dotnet` command. | Installed. `global.json` pins the version. |
| **`dotnet` CLI** | The command-line tool: `dotnet build`, `dotnet test`, `dotnet run`, `dotnet add package`. Rider runs the same commands behind its buttons. | Daily use |
| **Project (`.csproj`)** | One unit that compiles into one **assembly** (a `.dll` or `.exe`). | Each folder under `src/` and `tests/` |
| **Solution (`.slnx`)** | A list of projects that belong together, the file you open in Rider. `.slnx` is the new, readable XML format. | `SatisfactoryLedger.slnx` |
| **Project reference** | "Project A may use the code of project B." Without a reference, the compiler refuses. That's how we enforce part of the architecture. | Already set up between the modules |
| **Assembly** | The compiled output of a project. Architecture tests inspect assemblies. | — |
| **`internal` / `InternalsVisibleTo`** | `internal` means "visible only inside this assembly" (.NET has no package-private). `InternalsVisibleTo` in a `.csproj` names a friend assembly, usually the project's own tests, that may use those internal types too. | `SatisfactoryLedger.Catalog.csproj` → `Catalog.Tests` |
| **NuGet / package** | .NET's library store, like npm for JavaScript or Maven for Java. | `dotnet add package <Name>` |
| **Central Package Management** | All package versions in one file instead of in each project. | `Directory.Packages.props` |
| **`Directory.Build.props`** | Settings that automatically apply to every project in the folder tree. | Root of the repo |
| **Nullable reference types** | The compiler warns when something might be `null` and you don't check for it. It prevents the classic `NullReferenceException`. | On everywhere |
| **Warnings as errors** | Every compiler warning fails the build. Strict, but it keeps the code clean. | On everywhere |
| **Analyzers** | Extra code checks that run during the build (style, common mistakes). | `AnalysisLevel` in `Directory.Build.props` |
| **`record`** | A short C# way to define a type that's compared by its *values* instead of its identity. Ideal for value objects. | `Rate`, `ClockSpeed` (M1) |
| **Non-virtual by default (`virtual`/`override` vs `new`)** | In Java every method is virtual. In C# methods and properties are not, unless the base marks them `virtual` and the subclass `override`s them. A subclass member marked `new` *hides* the base member instead: there are two separate members, and which one runs depends on the variable's declared type, like a field with the same name in a Java subclass. | `ResourceItemGroupDto` (`Items` was hidden, so the base list stayed empty) |
| **Generic constraint (`where T : Base`)** | Limits a type parameter to `Base` or its subclasses, like Java's `<T extends Base>`. Unlike Java, generics are not erased: `Group<BeltDto>` and `Group<PipeDto>` are different types at runtime, with no shared base. `OfType<Group>()` without a type argument doesn't compile. | `TransportTierGroupDto<TTier> where TTier : TransportTierDto` |
| **Variance (`List<T>` vs `IEnumerable<out T>`)** | `List<Child>` is not a `List<Parent>`, and neither is `Dictionary<string, Child>`, just like in Java. `IEnumerable<out T>` is *covariant*, so an `IEnumerable<Child>` can be used as an `IEnumerable<Parent>`, roughly Java's `? extends`. Use `.Cast<Parent>()` to convert explicitly. Only interfaces and delegates can be variant, never classes: `Group<BeltDto>` is not a `Group<TransportTierDto>`, so `OfType<Group<TransportTierDto>>()` finds nothing. | Combining belt and pipe DTOs in one collection |
| **Extension methods need their namespace** | `builder.Configuration.GetConnectionString(...)` and `.WithTags(...)` are *extension methods*: static methods you call as if they were instance methods (Kotlin has these, Java doesn't). They're only visible when their namespace is imported with `using`. "No overload takes 1 argument" or "does not contain a definition" often just means a missing `using`. | `CatalogModule.cs` (`Microsoft.Extensions.Configuration`, `Microsoft.AspNetCore.Http`) |
| **Exception filters (`catch … when`)** | `catch (Exception e) when (e is JsonException or ArgumentException)` catches only when the condition is true; otherwise the exception passes through untouched, stack intact. Java's multi-catch (`catch (A \| B e)`) is the closest, but `when` can test anything. | `ImportCatalogHandler.ReadDocsFileAsync` |
| **`decimal` keeps its scale** | A `decimal` remembers how many decimals it was written with: `decimal.Parse("6.000000")` equals `6m` but prints as `6.000000`, in JSON too. Java's `BigDecimal` does the same (`stripTrailingZeros()`). In C# you drop them by dividing by `1.000…0m`. PostgreSQL `numeric` also keeps the scale you store. | `SatisfactoryTranslator.ParseGameDecimal` |
| **`private init`** | A setter that only works while the object is being created (in the constructor or an object initializer `new X { A = 1 }`). Halfway between `final` and a private setter. EF Core can still set it when it loads a row. | `CatalogImport.Items` |
| **`TimeProvider`** | .NET's injectable clock, like `java.time.Clock`: inject it instead of calling `DateTimeOffset.UtcNow`, so tests can control time. `TimeProvider.System` is the real clock. | `ImportCatalogHandler` |
| **`Guid.CreateVersion7()`** | A GUID (UUID) that starts with a timestamp, so new ids sort after old ones, which is good for database indexes. Built in since .NET 9; Java needs a library for UUIDv7. | `CatalogImportId.New()` |
| **CA1000: no static members on generic types** | An analyzer rule: `CatalogEntryChanges<T>.None` would have to be called with the type argument spelled out. Put the static on a non-generic class (`CatalogEntries.None<T>()`) instead, where the compiler can infer `T`. | `CatalogEntries.None<T>()` |
| **Transitive pinning (Central Package Management)** | `CentralPackageTransitivePinningEnabled` makes the versions in `Directory.Packages.props` also win for packages that only arrive *indirectly*, like Maven's `<dependencyManagement>`. Without it, two projects can end up with different EF Core versions (warning MSB3277). | `Directory.Packages.props` |
| **Local tool manifest (`dotnet-tools.json`)** | Pins command-line tools like `dotnet ef` per repo, like the Maven wrapper or `npx` with a `devDependency`. `dotnet tool restore` installs them. | `dotnet-tools.json` (repo root) |
| **Git submodule** | Another git repository checked out inside this one, pinned to **one commit**. The pin is stored in our repo; `.gitmodules` only records the URL (and the branch that `git submodule update --remote` would follow). Clone with `--recurse-submodules`, and CI needs `submodules: true`. Maven and npm have no direct equivalent; the closest is a Gradle composite build (`includeBuild`) of a pinned checkout. A `ProjectReference` into the submodule builds it from source with our SDK, but with **its own** `Directory.Build.props`, because MSBuild stops at the first one it finds walking up the folders. | `external/SatisfactorySaveNet` (ADR-0013) |
| **Paths: `/` works everywhere, `\` doesn't** | `@"Fixtures\Valid.json"` works on Windows only; CI runs on Linux. .NET accepts `/` on Windows too, so always write `/` (or use `Path.Combine`). | All fixture paths in the tests |
| **Reference assemblies** | When project A references project B, the compiler gives A a *reference assembly* of B: only B's public and internal surface, no method bodies. Change a method body in B and A isn't recompiled, because A's input didn't change. That makes builds fast, but anything that keys on A's own `.dll` (like a code generator) misses changes made in B. Gradle's compile avoidance works the same way (ABI-only classpath). | `SatisfactoryLedger.Api.csproj`, target `RegenerateOpenApiWhenReferencesChange` |
| **MSBuild target, `Inputs`/`Outputs`** | A target is a named build step, like a Maven plugin goal or a Gradle task. `BeforeTargets="X"` hooks it in before target `X`. With `Inputs` and `Outputs` MSBuild skips the target when every output is newer than every input, the same idea as Gradle's up-to-date check. Packages ship targets in a `build/*.targets` file that is imported into your project automatically. | `SatisfactoryLedger.Api.csproj` |
| **Records for values, classes for entities** | A `record` compares by value, like a Java `record`. That fits value objects (`BuildableId`, `ItemId`). An entity is compared by identity, so it's a plain `class` (`Machine`, `Provider`). Careful: a record with a collection property compares that collection *by reference*, so two equal-looking records with different `HashSet`s are not equal. | `World.Domain` |
| **Primary constructor on a class** | `class Provider(BuildableId id) : Buildable(id)` declares the constructor in the class header and passes `id` to the base constructor. Unlike a record, the parameter does **not** become a property. It's a captured variable you can use in the body, so expose it explicitly when you need it (`public LogisticsKind Kind { get; } = kind;`). | `Provider`, `Consumer`, `Logistics` |
| **`private protected`** | Visible to subclasses **in the same assembly** only. On the base constructor it means only this project can add subclasses. That gives a closed set of roles, like a Java `sealed` interface with `permits`. | `Buildable` |
| **Property patterns** | `output is Logistics { IsBelt: true }` checks the type and a property in one expression, and `switch` arms can add a `when` guard (`Machine machine when !machine.ProducesAnyOf(...)`). Java 21's record patterns come close, but only for records. | `FactoryDefinition.TraceMembers` |
| **`ILookup<TKey, TElement>`** | A read-only multimap from `ToLookup(...)`, like Guava's `ListMultimap`. Asking for a missing key returns an **empty** sequence instead of throwing, which makes graph walks short. | `WorldGraph` |
| **Value tuples** | `(HashSet<T> Machines, HashSet<T> Logistics) Trace()` returns two values without declaring a type, and the caller unpacks them with `var (a, b) = Trace();`. Java has nothing built in (you'd write a `record` or use a `Pair`); TypeScript returns `[a, b]`. The element names exist **only at compile time**: at runtime they're `Item1` and `Item2`, so a tuple is erased in the way generics aren't. Fine inside one class. Once the result has a meaning or a method of its own, give it a name: a private nested `record` is one line. | `FactoryDefinition.UpstreamTrace` (was a tuple) |
| **Name lookup: an enclosing namespace beats `using static`** | Inside `namespace SatisfactoryLedger.World.SaveFile.Tests`, the name `World` first finds the namespace `SatisfactoryLedger.World`, before any member imported with `using static`. So `World.Buildables` fails to compile even though a `using static` class has a property `World`. In Java a static import wins over a package name. The fix is a name that isn't also a namespace. | `TestWorldSave.Save` (was `World`) |
| **A type in the current namespace beats a `using` import** | If the namespace you're in has its own `CatalogRecipe`, then `using SatisfactoryLedger.Catalog.Contracts;` doesn't make `CatalogRecipe` mean the contract's type. The local one wins. Java is the other way round: a single-type import shadows a class of the same package. Use an alias, `using Contracts = SatisfactoryLedger.Catalog.Contracts;`, and write `Contracts.CatalogRecipe`. | `CatalogQueriesTests` |
| **`required` and `init` properties** | `public required string SessionName { get; init; }`: the compiler refuses `new StoredSnapshot { … }` until every `required` property is set, and `init` allows setting it only during creation. Immutable objects without a long constructor. Kotlin's non-null `val` in a constructor is the closest. | `StoredSnapshot` |
| **A closed set of outcomes as nested records** | `abstract record DefineFactoryOutcome` with a `private` constructor, and nested `sealed record Defined(…)`, `NameTaken`, … Only the nested records can derive from it, so the set is closed, and `switch` handles each case. It's a discriminated union without language support, like a Java `sealed interface … permits` with records, or a TypeScript union type. The overview asks for this: domain failures are results, not exceptions. | `DefineFactoryOutcome` |
| **Declared vs. effective accessibility of nested types** | A `public` type nested in an `internal` type is effectively internal: the outer type caps it. Reflection, and so ArchUnitNET, sees the **declared** `public`, and the rule "implementation types are internal" fails. Declare nested types `internal` and the code says what it means. | `DefineFactoryOutcome.Defined` |
| **`generated_code = true` in `.editorconfig`** | Marks files as generated, so analyzers skip them. `dotnet ef` generates migrations that can break rules such as CA1861 (constant arrays as arguments), and with warnings as errors the build would fail on code nobody writes by hand. | `.editorconfig`, `[**/Persistence/Migrations/*.cs]` |
| **IDE0130 (namespace doesn't match folder) only in the IDE** | The rule exists, and `.editorconfig` can raise it to a warning, but a command-line `dotnet build` didn't report it here, even with `RootNamespace` and `ProjectDir` made compiler-visible as the docs say. So a test checks it. Not every code-style rule runs in CI just because it's set. | `ArchitectureTests/SourceLayoutTests` |
| **`[GeneratedRegex]`** | `[GeneratedRegex(@"…")] private static partial Regex Namespace();`: a source generator writes the matching code at compile time, so nothing is parsed at runtime. Java compiles a `Pattern` at startup. The class must be `partial`. | `SourceLayoutTests` |
| **`ProjectReference` metadata: `SetConfiguration`, `PrivateAssets`** | `SetConfiguration="Configuration=Release"` builds a referenced project in another configuration, but **only when the referencing project is built on its own**: in a solution build, MSBuild ignores it for projects that aren't in the solution. `PrivateAssets="all"` stops the reference flowing on to projects that use yours, and with it the referenced project's NuGet packages, so they can be missing at runtime. | Tried in step 08, both removed |
| **`#if DEBUG` in a library built from source** | A library referenced as a project is compiled with **your** configuration, so its debug-only code runs in your Debug builds. A NuGet package is compiled once, usually in Release. | The fork's `StringSerializer` (step 08) |
| **XML comments can't contain `--`** | An `.csproj` is XML, and XML forbids `--` inside `<!-- … -->`. A command line such as `dotnet run --project …` in a comment breaks the project file (MSB4025). | `SatisfactoryLedger.MapExtractor.csproj` |
| **Top-level statements with an exit code** | `Program.cs` without a class or `Main`: the statements are the program, `args` is in scope, and `return 1;` sets the exit code, like `System.exit(1)` in Java. A local function at the end can use `args`. | `tools/SatisfactoryLedger.MapExtractor/Program.cs` |
| **Raw string literals (`"""`)** | A string between `"""` lines keeps its text as written: no escaping of quotes or backslashes, and the indentation of the closing `"""` is removed. Java has text blocks (`"""`) since 15; TypeScript has template literals. | Help text of the map tool |
| **Interpolated raw strings (`$$"""`)** | `$$"""{ "version": {{version}} }"""`: with two `$`, a single `{` is just a brace and `{{…}}` is a placeholder. Handy for JSON in tests, where the braces would otherwise all need escaping. | `ResourceNodeTableReaderTests` |
| **`BinaryPrimitives`** | Reads and writes numbers in a fixed byte order from a span: `BinaryPrimitives.ReadUInt32LittleEndian(bytes)`. Java's `ByteBuffer.order(ByteOrder.LITTLE_ENDIAN).getInt()`. | `UsmapPatcher` |
| **Pinning a vulnerable transitive dependency** | NuGet audits packages on restore and warns (NU1903) about known vulnerabilities, and with warnings as errors the build fails. A `PackageVersion` for the indirect package in `Directory.Packages.props` lifts it to a fixed version (transitive pinning), like a Maven `<dependencyManagement>` entry. | `Microsoft.Bcl.Memory` 9.0.14 for CUE4Parse |
| **Patterns in exception filters and `switch`** | `catch (Exception e) when (e is not (A or B))` and `case (Port.Out, Port.In or Port.Undirected):` combine type and value patterns with `not`, `or` and `and`. A `switch` can match a tuple of values at once. Java 21 has record patterns and `case A, B`, but not `not`, or patterns on tuples. | `SaveFileReader.Read`, `ConnectionBuilder.Build` |
| **Relational patterns** | `is FlowConduit { Capacity: < double.PositiveInfinity }` matches a type and compares a property in one go. Patterns can use `<`, `>`, `and`, `or`, `not`. | `SteadyState.Bottlenecks` |
| **`MinBy` / `MaxBy` and tuple deconstruction** | `.MinBy(entry => entry.Share)` returns the element with the smallest key, not the key (Java: `stream().min(comparing(...))`). `(double share, ItemId? item) = …` unpacks a tuple; `_` discards a part you don't need. | `SteadyState.Scarcest` |
| **`double.PositiveInfinity`** | A real value in IEEE doubles: `Math.Min(60, ∞)` is 60, `∞ - 1` is ∞. Handy as "no limit" in a simulation, with care when subtracting two infinities (NaN). | `SteadyState`: what a sink accepts |
| **UTF-8 string literals (`"…"u8`)** | `"text"u8` is a `ReadOnlySpan<byte>` with the UTF-8 bytes, made at compile time. It's like `"text".getBytes(StandardCharsets.UTF_8)` but without a runtime call. | `SaveFileReaderTests` |
| **Public test methods can't take internal types (CS0051)** | xUnit needs public test classes and methods, and a public method can't have an `internal` type as a parameter. In a `[Theory]`, pass the value as a string and `Enum.Parse` it inside the test. | `GameClassesTests` |
| **CA1859: concrete types on private members** | Java teaches "program to interfaces". For `private` methods, .NET's analyzer prefers the concrete type (`HashSet<T>` instead of `IReadOnlySet<T>`), because calls through an interface can't be devirtualized. Public signatures stay on interfaces. With warnings as errors, the build fails until you change it. | `FactoryDefinition.ReachableDownstream` |

## Backend

| Term | What it is | In this project |
|---|---|---|
| **ASP.NET Core** | The .NET framework for websites and web APIs. Receives HTTP requests and sends responses. | `SatisfactoryLedger.Api` |
| **Web API** | A program that the frontend talks to over HTTP with JSON, rather than a page you look at directly. | The backend as a whole |
| **System.Text.Json (STJ)** | .NET's built-in JSON library, the counterpart of Jackson. `JsonSerializer.Deserialize<T>(json)` turns JSON into objects. Attributes such as `[JsonPropertyName("x")]` work like Jackson's annotations. | Catalog importer (M2) |
| **STJ only sees public properties** | By default STJ reads and writes only **public** properties. Any other property is skipped silently, without an error. Unlike Jackson's `@JsonProperty`, `[JsonPropertyName]` only renames a property and does not include it. To include a non-public property, add `[JsonInclude]` (works on non-public properties since .NET 8), or make the property public. On an `internal` DTO class, public properties are still invisible outside the assembly. | `Catalog/Importer/*Dto.cs` |
| **STJ polymorphism (`[JsonPolymorphic]`, `[JsonDerivedType]`)** | Lets STJ pick a subclass from a *type discriminator* field in the JSON, like Jackson's `@JsonTypeInfo` + `@JsonSubTypes`. On the base class, `[JsonPolymorphic]` names the field and each `[JsonDerivedType]` maps one value to one subclass. | `GameDataGroupDto`, on the `NativeClass` field |
| **Unknown discriminators always throw** | When reading JSON, a discriminator value that isn't registered with `[JsonDerivedType]` throws `JsonException: Read unrecognized type discriminator id`. The option `UnknownDerivedTypeHandling = FallBackToBaseType` sounds like the fix, but it only affects *serialization* (writing a subtype that isn't registered). It does nothing for deserialization (checked on .NET 10). To skip unknown entries, filter them out first, e.g. with a `JsonDocument`. | `SatisfactoryImporter.DeserializeSupportedGroups` |
| **STJ creates the declared type** | STJ creates objects of exactly the declared property type. `List<TransportTierDto>` gives plain `TransportTierDto`s, never subclasses, and properties that only the subclass has (`mSpeed`) are dropped silently. `[JsonPolymorphic]` on a group class doesn't carry over to the group's elements. Fix it in the type: make the group generic, so each subclass declares its element type. Jackson behaves the same way without `@JsonTypeInfo`. | `BeltGroupDto : TransportTierGroupDto<BeltDto>` |
| **One discriminator per derived type** | STJ's `[JsonDerivedType(typeof(X), "a")]` maps one discriminator to one type, and each type can be registered only once. When the game spreads one concept over several sections (extractors live under three `NativeClass` values), give each section its own small subclass of a shared base. Jackson's `@JsonSubTypes.Type(names = {"a", "b"})` allows several names for one type; STJ doesn't. | `ExtractorGroupDto` and its three subclasses |
| **Minimal APIs** | The compact ASP.NET Core style: one line per endpoint (`app.MapGet("/items", ...)`) instead of controller classes. | All endpoints (M2+) |
| **Endpoint** | One URL + HTTP method combination, e.g. `GET /api/v1/blueprints`. | Chapter 05 |
| **Dependency injection (DI)** | Classes ask for what they need in their constructor, and the framework supplies it. That makes them swappable and testable. | Built into ASP.NET Core |
| **EF Core (Entity Framework Core)** | Microsoft's ORM: saves and loads C# objects to and from a database without hand-written SQL. | Persistence, from M2 |
| **EF1002: interpolated strings in raw SQL** | EF Core ships an analyzer that fails the build when you pass `$"…{x}…"` to `ExecuteSqlRawAsync`, the classic SQL-injection mistake. Use `ExecuteSqlAsync($"…{x}…")` instead: EF turns each `{x}` into a SQL parameter, like a JDBC `PreparedStatement`. Identifiers such as table names can't be parameters, so for those, build the text yourself from trusted values. | `LedgerApiFactory.ResetCatalogAsync` (table names from EF's model) |
| **ORM** | Object-Relational Mapper: translates between objects (code) and tables (database). | EF Core is one |
| **`DbContext`** | The EF Core class that represents a database connection plus a set of tables. We give each module its own. | M2 |
| **Migration** | A generated script that changes the database structure (adds a table or column) when your model changes. | M2+ |
| **PostgreSQL** | A free, widely used relational database. Runs in Docker. | ADR-0007, from M2 |
| **Docker / container** | Runs software (such as PostgreSQL) in an isolated box without installing it on your machine. | Started automatically by Aspire and Testcontainers |
| **.NET Aspire** | A tool that starts all parts of the app (API, database, frontend) with one command and shows a **dashboard** with logs and traces. | `SatisfactoryLedger.AppHost`: run this |
| **ServiceDefaults** | Aspire's shared setup for logging, health checks and resilience, added to every service with one line. | `SatisfactoryLedger.ServiceDefaults` |
| **OpenTelemetry** | Standard for *observability*: logs, metrics and traces. You can see what the app does and how long it takes. | Visible in the Aspire dashboard |
| **Health check** | A URL (`/health`) that tells whether the app and its database are working. | Mapped by ServiceDefaults |
| **EF Core change tracking** | Entities loaded through a `DbContext` are *tracked*: change a property, call `SaveChangesAsync()`, and EF writes an `UPDATE`. That's JPA's dirty checking, and the `DbContext` is roughly the `EntityManager`. `AsNoTracking()` skips tracking for read-only queries. | `ImportCatalogHandler` (tracked), `BrowseEndpoints` (`AsNoTracking`) |
| **EF Core migrations (`dotnet ef`)** | `dotnet ef migrations add <Name>` compares your model with the last snapshot and *generates* C# code that changes the schema. Like Flyway or Liquibase, but the scripts are generated instead of hand-written. `MigrateAsync()` applies them. | `Catalog/Persistence/Migrations/` |
| **Design-time factory (`IDesignTimeDbContextFactory`)** | `dotnet ef` needs to create your `DbContext` without starting the app. This factory tells it how. Creating a migration doesn't connect to a database. | `DesignTimeCatalogDbContextFactory` |
| **EF only maps what it can set** | Properties without a setter (`Id { get; }`) aren't mapped by convention, so the mapping lists every property. EF can only pass *scalar* properties to a constructor; complex properties and collections are set afterwards, through private setters or fields. | `CatalogEntityConfigurations.cs`, the private constructors of `Recipe` and `CatalogImport` |
| **EF collections must be `IList<T>`** | EF Core needs a collection it can create and add to: arrays and `IReadOnlyList<T>` are refused. Keep a private `List<T>` field for EF, expose a read-only view, and query the field with `EF.Property<T>(entity, "_field")`. | `Recipe._inputs` / `Recipe.Inputs`, `RecipeConfiguration` |
| **Value converter** | Converts a property to a column type and back, like JPA's `AttributeConverter`. Used for strongly typed ids: `ItemId` ⇄ `text`. | `HasConversion(id => id.Id, value => ItemId.Of(value))` |
| **Complex type / complex collection** | A value object stored *inside* its owner's row, like JPA's `@Embeddable`. A single one becomes columns (`items_added`); a collection is stored as JSON (`jsonb`) with `ToJson()`. New in EF Core 8 and 10. | `CatalogImport.Items`, `Recipe` inputs/outputs |
| **Primitive collection** | A `List<string>` mapped to one column. On PostgreSQL that's a native `text[]` array. | `CatalogImport.NoLongerInGame` |
| **Connection strings from Aspire** | `AddPostgres(...).AddDatabase("ledger")` plus `.WithReference(ledger)` in the AppHost gives the API an environment variable `ConnectionStrings__ledger`. The double underscore stands for `:` in configuration keys, so the code reads `GetConnectionString("ledger")`. Tests set the same key with `UseSetting`. | `AppHost.cs`, `CatalogDbContext.ConnectionStringName` |
| **`EnrichNpgsqlDbContext`** | Adds Aspire's extras (retries on transient errors, health check, tracing) to a `DbContext` you registered yourself. Use it instead of `AddNpgsqlDbContext` when you need your own Npgsql options, like a migrations table in your own schema. | `CatalogModule.AddCatalogModule` |
| **Minimal API parameter binding** | Handler parameters are filled by convention: route values, query string, services from DI, `IFormFile` and `[FromForm]` from a form upload, a body for complex types. Spring's argument resolvers, but inferred from the type and the route, mostly without annotations. | `ImportEndpoints.ImportAsync` |
| **Enums bind case-sensitively** | `?form=fluid` doesn't bind to `ItemForm.Fluid`, but the JSON output says `"fluid"`. Read a string and use `Enum.TryParse(value, ignoreCase: true, …)`. | `BrowseEndpoints.GetItemsAsync` |
| **`BadHttpRequestException` becomes 500 in Development** | In Development, minimal APIs *throw* when they can't bind a request (so you can debug it), and `UseExceptionHandler` turns any exception into a 500. `ExceptionHandlerOptions.StatusCodeSelector` keeps the 400. In Production they return 400 directly. | `Program.cs` |
| **`TypedResults` and `Results<A, B>`** | Endpoints return `Results<Created<T>, ValidationProblem>`, a union of possible results, so the OpenAPI document knows every status code. In Spring you'd add `@ApiResponse` annotations. A `ProblemHttpResult` doesn't reveal its code, hence `.ProducesProblem(422)`. | `ImportEndpoints`, `BrowseEndpoints` |
| **Antiforgery and file uploads** | Since .NET 8, a minimal API endpoint that binds `IFormFile` requires an antiforgery token, a protection against forged form posts from a logged-in browser (CSRF). An API without cookies has nothing to protect, so it says `.DisableAntiforgery()`. | `POST /api/v1/catalog/imports` |
| **Numbers as strings in OpenAPI** | ASP.NET's JSON defaults also *read* numbers sent as strings (`"5"`), so the OpenAPI document types every number as `number \| string`. `NumberHandling = Strict` keeps them plain numbers in the contract and the generated client. | `Program.cs` |
| **Scalar** | The interactive API documentation page, like Swagger UI. Open `/scalar/v1` while the API runs in Development. | `Program.cs`, `Scalar.AspNetCore` |

## Testing

| Term | What it is | In this project |
|---|---|---|

## API design

| Term | What it is | In this project |
|---|---|---|
| **REST** | A style of API design built around *resources* (blueprints, factories) and HTTP methods (GET = read, POST = create, PUT = replace, PATCH = change, DELETE = remove). | Chapter 05 |
| **Status code** | The number in an HTTP response: 200 OK, 201 Created, 404 Not Found, 422 business rule violated, and so on. | Chapter 05 |
| **JSON** | The text format in which the API and frontend exchange data. | — |
| **OpenAPI** | A machine-readable description of the whole API: all endpoints and data shapes. Generated by ASP.NET Core. | ADR-0006 |
| **Build-time OpenAPI (`Microsoft.Extensions.ApiDescription.Server`)** | A package that writes the OpenAPI document to a file on every build. It starts your `Program.cs` up to `builder.Build()`, asks the registered OpenAPI services for the document and stops, so no database or web server is needed. Like `springdoc-openapi-maven-plugin`, but without starting the app for real. The file name may only contain letters, digits, `_` and `-`. | `api/openapi.json`, CI step "Check OpenAPI contract is committed" |
| **Scalar** | A web page generated from the OpenAPI document where you can browse and try out the API. | Development |
| **Generated client** | TypeScript code generated *from* the OpenAPI document, so the frontend always matches the backend. | `web/src/app/api/` (M3) |
| **ProblemDetails** | A standard JSON format for error responses (RFC 9457). | All errors |
| **ETag / If-Match** | A version stamp on a resource. It prevents two edits from overwriting each other ("optimistic concurrency"). | Chapter 05 |
| **Versioning (`/api/v1`)** | The version in the URL, so you can make breaking changes later without breaking old clients. | All routes |
