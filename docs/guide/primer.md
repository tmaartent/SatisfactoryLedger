# Primer: the terms used in this guide

Every technical term in the guide, in plain language: what it is, and where you'll meet it in this project. Read a section when a chapter mentions a term you don't know. You don't need to learn all of it up front.

## .NET basics

| Term | What it is | In this project |
|---|---|---|
| **.NET 10** | Microsoft's free, cross-platform platform for running C# programs. Version 10 is the current *LTS* (Long Term Support, 3 years of updates). | Everything in `src/` and `tests/` |
| **C# 14** | The language version that comes with .NET 10. | All backend code |
| **SDK** | The toolkit for building .NET: compiler plus the `dotnet` command. | Installed. `global.json` pins the version. |
| **`dotnet` CLI** | The command-line tool: `dotnet build`, `dotnet test`, `dotnet run`, `dotnet add package`. Rider runs the same commands behind its buttons. | Daily use |
| **Project (`.csproj`)** | One unit that compiles into one **assembly** (a `.dll` or `.exe`). | Each folder under `src/` and `tests/` |
| **Solution (`.slnx`)** | A list of projects that belong together, the file you open in Rider. `.slnx` is the new, readable XML format. | `SatisfactoryLedger.slnx` |
| **Project reference** | "Project A may use the code of project B." Without a reference, the compiler refuses. That's how we enforce part of the architecture. | Already set up between the modules |
| **Assembly** | The compiled output of a project. Architecture tests inspect assemblies. | — |
| **`internal` / `InternalsVisibleTo`** | `internal` means "visible only inside this assembly" (.NET has no package-private). `InternalsVisibleTo` in a `.csproj` names a friend assembly, usually the project's own tests, that may use those internal types too. | `SatisfactoryLedger.Catalog.csproj` → `Catalog.Tests` |
| **NuGet / package** | .NET's library store, like npm for JavaScript or Maven for Java. | `dotnet add package <Name>` |
| **Central Package Management** | All package versions in one file instead of in each project. | `Directory.Packages.props` |
| **`Directory.Build.props`** | Settings that automatically apply to every project in the folder tree. | Root of the repo |
| **Nullable reference types** | The compiler warns when something might be `null` and you don't check for it. It prevents the classic `NullReferenceException`. | On everywhere |
| **Warnings as errors** | Every compiler warning fails the build. Strict, but it keeps the code clean. | On everywhere |
| **Analyzers** | Extra code checks that run during the build (style, common mistakes). | `AnalysisLevel` in `Directory.Build.props` |
| **`record`** | A short C# way to define a type that's compared by its *values* instead of its identity. Ideal for value objects. | `Rate`, `ClockSpeed` (M1) |
| **Non-virtual by default (`virtual`/`override` vs `new`)** | In Java every method is virtual. In C# methods and properties are not, unless the base marks them `virtual` and the subclass `override`s them. A subclass member marked `new` *hides* the base member instead: there are two separate members, and which one runs depends on the variable's declared type, like a field with the same name in a Java subclass. | `ResourceItemGroupDto` (`Items` was hidden, so the base list stayed empty) |
| **`abstract` member vs `virtual` with a default** | An `abstract` property has no body: every concrete subclass must `override` it, or the build fails, like an abstract method in Java. A `virtual` one with a default body compiles silently when a subclass forgets it, like a Java `default` method. Use `abstract` when every kind must answer for itself. An `override` can be a get-only auto-property set in the constructor (`public override X Demand { get; }`). | `Buildable.Demand`, `Production`, `Consumes` (step 111) |
| **Generic constraint (`where T : Base`)** | Limits a type parameter to `Base` or its subclasses, like Java's `<T extends Base>`. Unlike Java, generics are not erased: `Group<BeltDto>` and `Group<PipeDto>` are different types at runtime, with no shared base. `OfType<Group>()` without a type argument doesn't compile. | `TransportTierGroupDto<TTier> where TTier : TransportTierDto` |
| **Variance (`List<T>` vs `IEnumerable<out T>`)** | `List<Child>` is not a `List<Parent>`, and neither is `Dictionary<string, Child>`, just like in Java. `IEnumerable<out T>` is *covariant*, so an `IEnumerable<Child>` can be used as an `IEnumerable<Parent>`, roughly Java's `? extends`. Use `.Cast<Parent>()` to convert explicitly. Only interfaces and delegates can be variant, never classes: `Group<BeltDto>` is not a `Group<TransportTierDto>`, so `OfType<Group<TransportTierDto>>()` finds nothing. | Combining belt and pipe DTOs in one collection |
| **Extension methods need their namespace** | `builder.Configuration.GetConnectionString(...)` and `.WithTags(...)` are *extension methods*: static methods you call as if they were instance methods (Kotlin has these, Java doesn't). They're only visible when their namespace is imported with `using`. "No overload takes 1 argument" or "does not contain a definition" often just means a missing `using`. | `CatalogModule.cs` (`Microsoft.Extensions.Configuration`, `Microsoft.AspNetCore.Http`) |
| **Exception filters (`catch … when`)** | `catch (Exception e) when (e is JsonException or ArgumentException)` catches only when the condition is true; otherwise the exception passes through untouched, stack intact. Java's multi-catch (`catch (A \| B e)`) is the closest, but `when` can test anything. | `ImportCatalogHandler.ReadDocsFileAsync` |
| **`decimal` keeps its scale** | A `decimal` remembers how many decimals it was written with: `decimal.Parse("6.000000")` equals `6m` but prints as `6.000000`, in JSON too. Java's `BigDecimal` does the same (`stripTrailingZeros()`). In C# you drop them by dividing by `1.000…0m`. PostgreSQL `numeric` also keeps the scale you store. | `SatisfactoryTranslator.ParseGameDecimal` |
| **`(decimal)` of a `float` rounds to 7 digits** | Casting a `float` to `decimal` keeps at most 7 significant digits: `(decimal)320.83008f` is `320.8301`. Java's `new BigDecimal(320.83008f)` does the opposite and gives the exact binary value, `320.830078125`. Neither is the number the game showed, so round on purpose to the precision you mean. | `DroneRoutes.Of` (trip seconds and metres, to two decimals) |
| **Throw helpers: `ArgumentOutOfRangeException.ThrowIfNegativeOrZero(x)`** | Static guard methods on the exception types, like Guava's `Preconditions.checkArgument` or `Objects.requireNonNull`: one line, and the message names the argument by itself (the compiler passes its expression with `[CallerArgumentExpression]`). Also `ThrowIfNegative`, `ThrowIfNullOrWhiteSpace`, `ArgumentNullException.ThrowIfNull`. | `Pump.Create` (Catalog), `Storage.Create` |
| **`private init`** | A setter that only works while the object is being created (in the constructor or an object initializer `new X { A = 1 }`). Halfway between `final` and a private setter. EF Core can still set it when it loads a row. | `CatalogImport.Items` |
| **`TimeProvider`** | .NET's injectable clock, like `java.time.Clock`: inject it instead of calling `DateTimeOffset.UtcNow`, so tests can control time. `TimeProvider.System` is the real clock. | `ImportCatalogHandler` |
| **`Guid.CreateVersion7()`** | A GUID (UUID) that starts with a timestamp, so new ids sort after old ones, which is good for database indexes. Built in since .NET 9; Java needs a library for UUIDv7. Only to the millisecond: two made in the same one sort at random, so a test that needs one to be older uses fixed ids (`SnapshotFactoriesTests`). | `CatalogImportId.New()` |
| **Comparing `Guid`s: `CompareTo`** | `Guid` implements `IComparable<Guid>`, and `CompareTo` orders by the first group, then the second and third (unsigned), then the remaining bytes: the order of the written-out string, which is also how Postgres sorts a `uuid`. So "the lowest id" of v7 ids is "created first" in C# and in an `ORDER BY id` alike. Two v7 ids made in the same millisecond have random bits after the timestamp, so they aren't ordered by which came first. In Java, `UUID.compareTo` exists too; check its order against your database's before you rely on it. | `SnapshotFactories.Of` (step 121: the oldest factory owns a shared machine) |
| **CA1000: no static members on generic types** | An analyzer rule: `CatalogEntryChanges<T>.None` would have to be called with the type argument spelled out. Put the static on a non-generic class (`CatalogEntries.None<T>()`) instead, where the compiler can infer `T`. | `CatalogEntries.None<T>()` |
| **Transitive pinning (Central Package Management)** | `CentralPackageTransitivePinningEnabled` makes the versions in `Directory.Packages.props` also win for packages that only arrive *indirectly*, like Maven's `<dependencyManagement>`. Without it, two projects can end up with different EF Core versions (warning MSB3277). | `Directory.Packages.props` |
| **Local tool manifest (`dotnet-tools.json`)** | Pins command-line tools like `dotnet ef` per repo, like the Maven wrapper or `npx` with a `devDependency`. `dotnet tool restore` installs them. | `dotnet-tools.json` (repo root) |
| **Git submodule** | Another git repository checked out inside this one, pinned to **one commit**. The pin is stored in our repo; `.gitmodules` only records the URL (and the branch that `git submodule update --remote` would follow). Clone with `--recurse-submodules`, and CI needs `submodules: true`. Maven and npm have no direct equivalent; the closest is a Gradle composite build (`includeBuild`) of a pinned checkout. A `ProjectReference` into the submodule builds it from source with our SDK, but with **its own** `Directory.Build.props`, because MSBuild stops at the first one it finds walking up the folders. | `external/SatisfactorySaveNet` (ADR-0013) |
| **Paths: `/` works everywhere, `\` doesn't** | `@"Fixtures\Valid.json"` works on Windows only; CI runs on Linux. .NET accepts `/` on Windows too, so always write `/` (or use `Path.Combine`). | All fixture paths in the tests |
| **Reference assemblies** | When project A references project B, the compiler gives A a *reference assembly* of B: only B's public and internal surface, no method bodies. Change a method body in B and A isn't recompiled, because A's input didn't change. That makes builds fast, but anything that keys on A's own `.dll` (like a code generator) misses changes made in B. Gradle's compile avoidance works the same way (ABI-only classpath). | `SatisfactoryLedger.Api.csproj`, target `RegenerateOpenApiWhenReferencesChange` |
| **MSBuild target, `Inputs`/`Outputs`** | A target is a named build step, like a Maven plugin goal or a Gradle task. `BeforeTargets="X"` hooks it in before target `X`. With `Inputs` and `Outputs` MSBuild skips the target when every output is newer than every input, the same idea as Gradle's up-to-date check. Packages ship targets in a `build/*.targets` file that is imported into your project automatically. | `SatisfactoryLedger.Api.csproj` |
| **Records for values, classes for entities** | A `record` compares by value, like a Java `record`. That fits value objects (`BuildableId`, `ItemId`). An entity is compared by identity, so it's a plain `class` (`Machine`, `Provider`). Careful: a record with a collection property compares that collection *by reference*, so two equal-looking records with different `HashSet`s are not equal. | `World.Domain` |
| **Primary constructor on a class** | `class Provider(BuildableId id) : Buildable(id)` declares the constructor in the class header and passes `id` to the base constructor. Unlike a record, the parameter does **not** become a property. It's a captured variable you can use in the body, so expose it explicitly when you need it (`public LogisticsKind Kind { get; } = kind;`). | `Provider`, `Consumer`, `Logistics` |
| **`private protected`** | Visible to subclasses **in the same assembly** only. On the base constructor it means only this project can add subclasses. That gives a closed set of roles, like a Java `sealed` interface with `permits`. | `Buildable` |
| **Property patterns** | `output is Logistics { IsBelt: true }` checks the type and a property in one expression, and `switch` arms can add a `when` guard (`Machine machine when !machine.ProducesAnyOf(...)`). Without a type it's a null check too: `buildables.GetValueOrDefault(id) is { BuildableKind: BuildableKind.Station }` is false for a missing id. Java 21's record patterns come close, but only for records. | `FactoryDefinition.TraceMembers`; `WorldArrangement.Make` (`IsStation`, step 128) |
| **`ILookup<TKey, TElement>`** | A read-only multimap from `ToLookup(...)`, like Guava's `ListMultimap`. Asking for a missing key returns an **empty** sequence instead of throwing, which makes graph walks short. | `WorldGraph` |
| **Value tuples** | `(HashSet<T> Machines, HashSet<T> Logistics) Trace()` returns two values without declaring a type, and the caller unpacks them with `var (a, b) = Trace();`. Java has nothing built in (you'd write a `record` or use a `Pair`); TypeScript returns `[a, b]`. The element names exist **only at compile time**: at runtime they're `Item1` and `Item2`, so a tuple is erased in the way generics aren't. Fine inside one class. Once the result has a meaning or a method of its own, give it a name: a private nested `record` is one line. | `FactoryDefinition.UpstreamTrace` (was a tuple) |
| **A value tuple as a dictionary key** | `Dictionary<(OutputDestinationKind Kind, StoredFactory? Factory), double>` adds up per kind and factory without a key class: a `ValueTuple` has `Equals` and `GetHashCode` over its parts. Each part keeps its own equality, so `StoredFactory`, a class, matches by reference: fine here, as every key comes from one dictionary of owners. Java needs a `record` (or `List.of(a, b)`) as the key. | `FactoryOutputs.Of` |
| **`OfType<T>()` drops nulls** | `items.Select(Maybe).OfType<Thing>()` keeps the non-null results and turns `IEnumerable<Thing?>` into `IEnumerable<Thing>`: `OfType` is a type test, and null is no `Thing`. Java's `.filter(Objects::nonNull)` keeps the element type as it was. | `FactoryDefinition.Trace.Outputs` |
| **Name lookup: an enclosing namespace beats `using static`** | Inside `namespace SatisfactoryLedger.World.SaveFile.Tests`, the name `World` first finds the namespace `SatisfactoryLedger.World`, before any member imported with `using static`. So `World.Buildables` fails to compile even though a `using static` class has a property `World`. In Java a static import wins over a package name. The fix is a name that isn't also a namespace. | `TestWorldSave.Save` (was `World`) |
| **A type in the current namespace beats a `using` import** | If the namespace you're in has its own `CatalogRecipe`, then `using SatisfactoryLedger.Catalog.Contracts;` doesn't make `CatalogRecipe` mean the contract's type. The local one wins. Java is the other way round: a single-type import shadows a class of the same package. Use an alias, `using Contracts = SatisfactoryLedger.Catalog.Contracts;`, and write `Contracts.CatalogRecipe`. | `CatalogQueriesTests` |
| **`required` and `init` properties** | `public required string SessionName { get; init; }`: the compiler refuses `new StoredSnapshot { … }` until every `required` property is set, and `init` allows setting it only during creation. Immutable objects without a long constructor. Kotlin's non-null `val` in a constructor is the closest. | `StoredSnapshot` |
| **A closed set of outcomes as nested records** | `abstract record DefineFactoryOutcome` with a `private` constructor, and nested `sealed record Defined(…)`, `NameTaken`, … Only the nested records can derive from it, so the set is closed, and `switch` handles each case. It's a discriminated union without language support, like a Java `sealed interface … permits` with records, or a TypeScript union type. The overview asks for this: domain failures are results, not exceptions. | `DefineFactoryOutcome`; `FuelBurn` (`Known`, `NotKnown`, `NoDroneRefuels`, step 112) |
| **Declared vs. effective accessibility of nested types** | A `public` type nested in an `internal` type is effectively internal: the outer type caps it. Reflection, and so ArchUnitNET, sees the **declared** `public`, and the rule "implementation types are internal" fails. Declare nested types `internal` and the code says what it means. | `DefineFactoryOutcome.Defined` |
| **`generated_code = true` in `.editorconfig`** | Marks files as generated, so analyzers skip them. `dotnet ef` generates migrations that can break rules such as CA1861 (constant arrays as arguments), and with warnings as errors the build would fail on code nobody writes by hand. | `.editorconfig`, `[**/Persistence/Migrations/*.cs]` |
| **IDE0130 (namespace doesn't match folder) only in the IDE** | The rule exists, and `.editorconfig` can raise it to a warning, but a command-line `dotnet build` didn't report it here, even with `RootNamespace` and `ProjectDir` made compiler-visible as the docs say. So a test checks it. Not every code-style rule runs in CI just because it's set. | `ArchitectureTests/SourceLayoutTests` |
| **`[GeneratedRegex]`** | `[GeneratedRegex(@"…")] private static partial Regex Namespace();`: a source generator writes the matching code at compile time, so nothing is parsed at runtime. Java compiles a `Pattern` at startup. The class must be `partial`. | `SourceLayoutTests`, `Translator/ClearanceDataParser.cs` (Catalog) |
| **`ProjectReference` metadata: `SetConfiguration`, `PrivateAssets`** | `SetConfiguration="Configuration=Release"` builds a referenced project in another configuration, but **only when the referencing project is built on its own**: in a solution build, MSBuild ignores it for projects that aren't in the solution. `PrivateAssets="all"` stops the reference flowing on to projects that use yours, and with it the referenced project's NuGet packages, so they can be missing at runtime. | Tried in step 08, both removed |
| **`#if DEBUG` in a library built from source** | A library referenced as a project is compiled with **your** configuration, so its debug-only code runs in your Debug builds. A NuGet package is compiled once, usually in Release. | The fork's `StringSerializer` (step 08) |
| **XML comments can't contain `--`** | An `.csproj` is XML, and XML forbids `--` inside `<!-- … -->`. A command line such as `dotnet run --project …` in a comment breaks the project file (MSB4025). | `SatisfactoryLedger.MapExtractor.csproj` |
| **Top-level statements with an exit code** | `Program.cs` without a class or `Main`: the statements are the program, `args` is in scope, and `return 1;` sets the exit code, like `System.exit(1)` in Java. A local function at the end can use `args`. | `tools/SatisfactoryLedger.MapExtractor/Program.cs` |
| **Raw string literals (`"""`)** | A string between `"""` lines keeps its text as written: no escaping of quotes or backslashes, and the indentation of the closing `"""` is removed. Java has text blocks (`"""`) since 15; TypeScript has template literals. | Help text of the map tool |
| **Interpolated raw strings (`$$"""`)** | `$$"""{ "version": {{version}} }"""`: with two `$`, a single `{` is just a brace and `{{…}}` is a placeholder. Handy for JSON in tests, where the braces would otherwise all need escaping. | `ResourceNodeTableReaderTests` |
| **`BinaryPrimitives`** | Reads and writes numbers in a fixed byte order from a span: `BinaryPrimitives.ReadUInt32LittleEndian(bytes)`. Java's `ByteBuffer.order(ByteOrder.LITTLE_ENDIAN).getInt()`. | `UsmapPatcher` |
| **Pinning a vulnerable transitive dependency** | NuGet audits packages on restore and warns (NU1903) about known vulnerabilities, and with warnings as errors the build fails. A `PackageVersion` for the indirect package in `Directory.Packages.props` lifts it to a fixed version (transitive pinning), like a Maven `<dependencyManagement>` entry. | `Microsoft.Bcl.Memory` 9.0.14 for CUE4Parse |
| **Patterns in exception filters and `switch`** | `catch (Exception e) when (e is not (A or B))` and `case (Port.Out, Port.In or Port.Undirected):` combine type and value patterns with `not`, `or` and `and`. A `switch` can match a tuple of values at once. Java 21 has record patterns and `case A, B`, but not `not`, or patterns on tuples. | `SaveFileReader.Read`, `ConnectionBuilder.Build` |
| **Relational patterns** | `is FlowConduit { Capacity: < double.PositiveInfinity }` matches a type and compares a property in one go. Patterns can use `<`, `>`, `and`, `or`, `not`. | `SteadyState.Bottlenecks` |
| **`MinBy` / `MaxBy` and tuple deconstruction** | `.MinBy(entry => entry.Share)` returns the element with the smallest key, not the key (Java: `stream().min(comparing(...))`). `(double share, ItemId? item) = …` unpacks a tuple; `_` discards a part you don't need. | `SteadyState.Scarcest` |
| **`double.PositiveInfinity`** | A real value in IEEE doubles: `Math.Min(60, ∞)` is 60, `∞ - 1` is ∞. Handy as "no limit" in a simulation, with care when subtracting two infinities (NaN). | `SteadyState`: what a sink accepts |
| **Extended property patterns** | `is InventoryItem { ItemType.Length: > 0 } item && item.ExtraProperty is IntProperty { Value: > 0 } count` checks a type, a nested property and a value, and names the matches, in one condition. Java 21 has record patterns, but not property paths (`ItemType.Length`) or relational checks inside them. | `SaveFileReader.StockOf` |
| **One type per file is a convention, not a compiler rule** | Java requires a public class to live in its own file, named after it. The C# compiler accepts any number of types in a file, under any name. Here the build enforces one type per file anyway, with StyleCop.Analyzers: SA1402 (one type per file; `stylecop.json` makes it count records, interfaces, enums and structs too, not only classes) and SA1649 (the file is named after the type). Every other StyleCop rule is off in `.editorconfig`. A type marked `file` is visible only inside its file, so it stays with the type it serves. | `stylecop.json`, `.editorconfig`, `Directory.Build.props` |
| **Extension members (C# 14)** | An `extension(FlowResult result) { … }` block in a static class adds methods *and properties* to a type you don't change, so `result.Settled` reads like a property of `FlowResult`. Before C# 14 only extension methods existed (`static bool Settled(this FlowResult r)`). Java has neither; Kotlin's extension functions and properties are the closest. Here they keep queries only tests need out of production code. | `tests/SatisfactoryLedger.World.Domain.Tests/FlowResultQueries.cs` (linked into the other World test projects) |
| **Local functions** | `bool Takes(int k, ItemId item) => …` declared inside a method, using the method's variables (`rules`, `named`). Java has only lambdas for that, and those can't be recursive or generic as easily. Keep them short; when one grows, make it a method. | `SteadyState.SendSorted` |
| **`Zip` into tuples, and `OrderBy` is stable** | `stored.Zip(matches)` pairs two sequences element by element into `(First, Second)` tuples, stopping at the shorter one; `foreach ((StoredFactory factory, MachineMatch match) in …)` deconstructs each pair. Java's streams have no `zip` (Guava's `Streams.zip` or an index loop); TypeScript neither (lodash `zip`). `OrderBy` is a stable sort, like Java's `sorted` on an ordered stream: equal keys keep the order given. | `SnapshotFactories.Of`; `MachineMatch.In` (`OrderBy(factory => factory.Id)`) |
| **Static extension members (C# 14)** | An `extension(T)` block (see *Extension members* above) can add **static** members too, called on the type: `extension(AnalysisDocument) { public static AnalysisDocument Compute(FlowNetwork n) … }` keeps `AnalysisDocument.Compute(…)` working although the record moved to `World.Contracts` and the method to `World.Simulation`. It resolves only where that namespace is imported, so `World` (which doesn't import it) can't call it. Java has no extensions at all; Kotlin can only extend a class's companion object. | `World.Simulation/NetworkAnalysis.cs`, `DocumentToNetwork.cs`; `World/Analysis/NetworkToDocument.cs` |
| **A `using` alias settles a name clash** | Two imported namespaces with a `MachineLimit` each give CS0104 (ambiguous). `using MachineLimit = SatisfactoryLedger.World.Contracts.Analysis.MachineLimit;` wins over both, for that file only. Java has no aliases: you write the fully qualified name. | `World.Tests/StockFindingsTests.cs`, `FlowNetworkDocumentTests.cs` |
| **`using` declaration: dispose at the end of the scope** | `using Solver solver = Solver.CreateSolver("GLOP")!;` without braces disposes `solver` when the method ends, like Java's try-with-resources but without the extra block. OR-Tools' .NET API is generated (SWIG) around native C++ objects, so its `Solver` is `IDisposable`: disposing frees the native memory at once instead of waiting for the garbage collector's finaliser. | `World.Simulation/LinearProgramme.cs` |
| **OR-Tools: a solution goes stale when the model changes** | After `Solve()`, changing any bound (`SetBounds`) or coefficient makes the solution count as out of date, and `SolutionValue()` then quietly returns 0. It doesn't throw. Read every value you need *before* changing the model. Found while freezing variables for what-ifs: they froze at 0. Hibernate's detached entities fail more loudly. | Step log `29-lp-solver-e-the-lp-starts-the-sweep.md` (the what-ifs that hit it were removed with the full LP) |
| **A source file linked into another test project** | `<Compile Include="..\Other.Tests\TestFlow.cs" Link="TestFlow.cs" />` compiles one file into a second project, so both test suites build networks the same way without a shared helper library. Java would need a test-jar dependency or a `testFixtures` source set (Gradle). The file keeps its own namespace, so the second project imports it. | `World.Simulation.Tests.csproj` (`TestFlow.cs`, `Items.cs`) |
| **A local function that captures nothing must be `static`** | The analyzer (IDE0062, an error with warnings as errors) asks for `static HashSet<string> Fuel() => …` when the local function uses none of the method's variables. `static` then guarantees it captures nothing, so no closure object is made. Java lambdas have no such keyword; capture is implicit. | `DronePortFindingsTests.Analyse`; `SteadyState.AskedItems` (`Ask` captures `asked`, so it isn't static) |
| **`GZipStream`** | Wraps a stream and decompresses as you read: `new GZipStream(File.OpenRead(path), CompressionMode.Decompress)`. Java's `GZIPInputStream`. A 4 MB text fixture is 224 KB this way. | `FlowText.ReadGzip` |
| **`Func<T, TResult>` as a parameter** | A delegate type: `Func<TestFlow, TestFlow> station` takes a lambda, `flow => flow.StationBurning("station", fuel)`. Java's `Function<T, R>` or `UnaryOperator<T>`; TypeScript's `(flow: TestFlow) => TestFlow`. `Action<T>` is the one without a result, like `Consumer<T>`. | `SteadyStateTests.FuelLine` |
| **`dynamic`** | A variable typed `dynamic` is checked at **runtime**: `p.Property.Values` compiles whatever `p` is, and fails only when run. Handy in a throwaway spike that pokes at an unknown library model, like JavaScript objects. Not in product code: no compile-time checking, slower. Java has nothing like it (reflection is the closest). **Extension methods don't bind on `dynamic`:** `((dynamic)x).Name.Split('.').Reverse()` fails at runtime, because LINQ's `Reverse` is an extension method; cast to the real type first. | The step 14 and 15 spikes (deleted) |
| **Wolverine handlers** | A class whose name ends in `Handler` with a `Handle`/`HandleAsync` method: the first parameter is the message, the rest are services. Wolverine finds it by convention and generates the calling code at startup (since 6.x that needs the `WolverineFx.RuntimeCompilation` package). Spring's `@RabbitListener` on a method. | `SatisfactoryLedger.AnalysisService.SnapshotImportedHandler` |
| **Transactional outbox with `IDbContextOutbox<T>`** | `outbox.DbContext.Add(…)`, `await outbox.PublishAsync(message)`, `await outbox.SaveChangesAndFlushMessagesAsync()`: the data and the outgoing message go into one transaction, and the message is sent after the commit. Spring Modulith's event publication registry, or Debezium, are the Java equivalents. | `ImportSaveHandler` |
| **EF's retrying execution strategy vs. your own transaction** | A retrying strategy (Aspire's default for Npgsql) refuses a transaction it didn't start. Run the work through `CreateExecutionStrategy().ExecuteAsync(…)`, or, when a library opens the transaction itself, turn retries off for that `DbContext`. | **A style budget per component** | `angular.json` warns when one component's styles pass 4 kB, and fails the build at 8 kB, besides the budget of the whole initial bundle. A component's styles are encapsulated (scoped to it, like CSS modules), so a rule two pages share lives in `styles.scss`, unscoped. Maven and webpack have nothing like it built in. | `map-page.scss`, `styles.scss` (`.area-select`, `.arrangements .run`) |
| **`computed` with `equal`** | `computed(fn, { equal: (a, b) => a?.id === b?.id })` tells its readers of a change only when the id changes, though `fn` makes a new object each time: readers (an `effect`) don't run again for an equal value. RxJS's `distinctUntilChanged(comparator)`; plain Java has no counterpart. | `ArrangementPage.selectedRun` |
| **Reading a canvas map from Playwright** | A Leaflet map on a canvas has nothing in the page to measure. `page.addInitScript` runs before the page's scripts; a setter on `window.L` sees Leaflet arrive (1.9 sets it as it loads), and `L.Map.addInitHook` then hands the test every map made, to read `getBounds()`. No test-only code in `src/`. | `e2e/arrangement.spec.ts` (`catchMaps`, `shown`) |
| **Dev-server proxy** | `proxy.conf.js` passes `/api` from `ng serve` on to the API, so the app calls relative URLs and needs no CORS. Like a Vite or webpack proxy. | `web/proxy.conf.js` |
| **`AddJavaScriptApp`** | Aspire's resource for an npm app: runs an npm script and passes `WithReference` addresses as environment variables (`services__api__https__0`). | `AppHost.cs` |
| **`afterNextRender(() => …)`** | Runs once, after Angular has put the component on the page. That's the moment for a library that needs a real DOM element, like Leaflet. Like `@PostConstruct`, but for the view. | `world/map/map-page.ts` `createMap` |
| **`untracked(() => …)`** | Inside an `effect` or `computed`, reads signals without making them dependencies: the effect doesn't rerun when they change. | **ng-openapi-gen skips models it thinks are unused** | It writes only models an operation reaches. | **`viewChild.required<ElementRef>('map')`** | A signal holding an element from the template (`<div #map>`). | `world/map/map-page.ts` |
| **`effect()` to drive a non-Angular library** | Leaflet knows nothing about signals. An effect reads the signals (data, filter, factory) and redraws a layer whenever one of them changes. | `world/map/map-page.ts` `drawMachines` |
| **A signal holding a `Set` needs a new `Set`** | Quirk: a signal compares old and new with `Object.is`, so `chosen().add(id)` changes the set but nobody hears it. Every change builds a new set (`signal.update(s => toggle(s, id))`). Same as React's state, unlike a Java `Set` behind an observable bean. Typed `ReadonlySet<string>` so `add` doesn't even compile on it. | `FactoryDraft.chosen` (`world/factory-draft.ts`), `area/selection.ts` `toggle` |
| **A service per page: `@Injectable()` without `providedIn`** | `providedIn: 'root'` makes one instance for the whole app, like a singleton Spring bean. Leave it out and list the class in a component's `providers: [...]`: that component and everything inside it (its view children too) share one instance, made with the component and destroyed with it, effects and all. Closest in Spring: a bean in a custom scope tied to one page. One page's half-made state can't leak into the next. | `FactoryPage` `providers: [FactoryDraft]`, `world/factory-draft.ts` |
| **A route's `providers` outlive the route** | Quirk: `providers` on a route make an injector when the route is first used, and keep it for the app's life: leaving the route doesn't destroy it. So a per-page service on a route is a singleton of that route, not of the visit. A component's `providers` go with the component. | `AreaPage` `providers: [ownDraftOrThePages]`, not on the `/area` route |
| **`useFactory` with `inject(X, { skipSelf: true, optional: true })`** | A provider that looks one level up first: `skipSelf` skips the component's own injector, `optional` gives `null` instead of an error when no parent has one. `?? new X()` then makes its own; inside a factory, `new X()` can still `inject()`, since it runs in an injection context. Use the parent's bean if there is one, else your own: in Spring, `ObjectProvider.getIfAvailable(X::new)`. | `world/factory-draft.ts` `ownDraftOrThePages` |
| **An event from a service: `Subject` + `takeUntilDestroyed()`** | A signal holds a state, and a signal set to the same value tells nobody, so "saved again" is lost. | **Fake timers with signals: `vi.useFakeTimers()` + `TestBed.tick()`** | An `effect` doesn't run when its signal changes, but at the next change detection; in a test of a service, `TestBed.tick()` runs it. | **Capture phase (`addEventListener(…, { capture: true })`)** | A DOM event travels down from the page to the element clicked, then bubbles back up. | **`:host ::ng-deep`** | Component styles are scoped by default, so they can't reach HTML a library creates (Leaflet's tooltips). `::ng-deep` lets them through; `:host` keeps that inside this component. | `world/map/map-page.scss` |
| **`allowedCommonJsDependencies`** | Angular's build expects ES modules. An older CommonJS package (Leaflet 1.9) works, but warns until it's listed here. | `angular.json` |
| **ESLint / angular-eslint** | The JavaScript world's linter: a separate tool, with its own command, unlike .NET's analyzers, which run inside `dotnet build`. angular-eslint adds the rules for Angular, templates included (a `@for` without `track`, a click handler with no keyboard equivalent). | **Prettier** | A formatter: it decides only layout (wrapping, quotes, commas), never what the code does, and has hardly any options, on purpose. | **`strictTemplates`** | Type-checks Angular templates as strictly as TypeScript code: an input bound to the wrong type, or a property that might be null, fails the build. Without it, much of a template is checked loosely. | `web/tsconfig.json` |
| **`tsc` doesn't check templates** | `npx tsc -p tsconfig.app.json --noEmit` type-checks the TypeScript only; a template's bindings are checked by the Angular compiler, so by `ng build` or `ng test`. Run `ng build` before calling a type change done. | `AreaPage.selectedOwners` (step 125) |

### Angular compared with a Node.js backend and with React

Angular runs in the **browser**; Node.js is only its toolchain (`ng serve`, `ng build`, npm). It feels like a backend because it's built like one: DI, services, decorators, a router. NestJS, a Node backend framework, copied that design, and both feel like Spring.

| | Angular | Node.js backend (Express / NestJS) |
|---|---|---|
| **Runs where** | In the browser, one instance per user tab | On a server, one process for all users |
| **State** | In memory, per user, for as long as the tab is open | In a database; memory is shared by all users |
| **Produces** | What the user sees (the DOM) | HTTP responses |
| **DI** | Built in: `inject(Api)`, `providedIn: 'root'` | Express: none. NestJS: Angular-style |
| **Concurrency** | One user, one thread; awaits HTTP calls | Many users on one event loop; blocking work stalls everyone |
| **Security** | Trusts nothing it holds: the user can change the code | The trust boundary: validates input, enforces access |
| **Tests** | Components in a fake DOM (`world/findings.spec.ts`) | Over HTTP, like `WebApplicationFactory` here |

An Angular service such as `shared/catalog-names.ts` looks like a Spring `@Service` singleton, but it's a singleton **per browser tab**. It's closer to a session-scoped bean.

| | Angular | React |
|---|---|---|
| **What it is** | A whole framework: router, HTTP client, forms, DI, test setup, CLI. Like Spring Boot | A rendering library. Router, data fetching and state come from other libraries (React Router, TanStack Query, Next.js) |
| **Templates** | HTML files with their own syntax (`@if`, `@for`, `[value]`, `(click)`), compiled ahead of time | JSX: HTML-like syntax inside TypeScript, so templates are code |
| **Components** | Classes with `@Component`; inputs via `input()` | Functions; props are parameters |
| **State** | Signals (`signal`, `computed`, `effect`): only what depends on a change is updated | `useState` and hooks: the component function runs again, and React compares the result |
| **Async data** | `resource()` or RxJS | `useEffect`, or TanStack Query |
| **DI** | Built in, hierarchical | None: Context, or passing props down |
| **Styles** | Scoped per component (`styleUrl`) | Your choice: CSS modules, Tailwind, CSS-in-JS |

**In this project:**
- **DI:** `CatalogNames` is injected wherever names are shown. React would pass it down or put it in a Context.
- **Signals:** the machine filter in `world/findings.ts` is a `computed()` over `findings()` and `limitFilter()`. React would run the component again and use `useMemo` to keep that cheap.
- **One toolchain:** the CLI, `HttpClient` and Angular Material came as one set. With React you'd choose a bundler, router, data library and component library separately.

### Phones and touch screens in CSS

Java has no counterpart for this part: in a browser, the layout follows the screen through CSS, not code.

- **`@media (max-width: 599px)`** applies rules only on narrow screens (`app.scss`, `sidebar/sidebar.scss`, `world/map/map-page.scss`). Jsdom, which the tests run in, has no screen and applies none of them: test the behaviour, and look at the layout in a browser.
- **`@media (hover: none)`** asks about the input, not the size: true where nothing can hover, as on a phone or a tablet (`world/map/map-page.scss`, the shift and ctrl hint). A narrow desktop window still has a mouse.
- **`dvh`, not `vh`.** `100vh` on a phone's browser is the screen's height *including* the address bar, so the page's bottom is cut off; `100dvh` is the height actually shown (`app.scss`).
- **A host binding** (`host: { '[class.closed]': 'tabs.collapsed()' }` in `sidebar/sidebar.ts`) sets a class on the component's own element, which its stylesheet reaches with `:host(.closed)`. Like an attribute a JSP tag writes on its own element, but kept up to date.
- **`setPointerCapture`** (`sidebar/sidebar.ts`, `grab`) sends a finger's later moves and its lifting to the element it went down on, even once it has left it: a swipe that ends beside the handle still counts.
- **`window.matchMedia(query)`** asks the same question from code (`sidebar/sidebar-tabs.ts`, `closeWhereItCovers`): `.matches` is true when the media query applies now. Jsdom has no `matchMedia`, so the code calls it with `?.()` and the test stubs it with `vi.stubGlobal`.
- **A finger's drag fires pointer events, not mouse events.** A browser makes `mousedown`/`mouseup`/`click` of a tap, for old pages, but not `mousemove` of a drag. Code that should work by touch listens to `pointerdown`/`pointermove`/`pointerup` (`world/map/area-selection.ts`); `isPrimary` tells the first finger from a second one in a pinch. And `touch-action: none` on the element, or the browser scrolls the page with the drag.
- **TypeScript narrowing doesn't reach into a callback for a `let`.** After `if (mode === 'offer') return;`, `mode` is `'add' | 'remove'` on the next line, but not inside `chosen.update((c) => … mode …)`: the callback might run after `mode` changed. Copy it to a `const` first (`world/area/area-page.ts`, `listenForBoxes`). Java's rule that a lambda may only capture effectively final variables avoids the question altogether.
- **A stubbed `matchMedia` needs `addListener` and `removeListener`.** Angular Material's `BreakpointObserver` listens to media queries; a stub that returns only `{ matches }` throws inside it, and Vitest then fails the run on an unhandled error although every test passed (`world/map/map-page.spec.ts`).
- **A global style can lose to a library's, at equal weight.** Angular Material puts its components' styles in the page after `styles.scss`, so between two selectors of the same specificity Material's wins. `.area-select` lost to Material's `.mat-mdc-mini-fab`; `button.area-select` (an element and a class) wins (`styles.scss`).
- **A three.js camera's `fov` is its upright angle of view.** How much fits across follows from the width-to-height ratio (`aspect`): on a screen higher than wide, less than fits from top to bottom. Framing for a phone means standing further back (`world/area/framing.ts`).
- **The 3D stage (`Stage`, `world/stage/stage.ts`)** is where both 3D views draw: the renderer at its element's size, the camera turned by dragging, presses, framing and the arrows of a splitter. A **press** is a click or a tap: a pointer let go within `PressReach` (4 px) of where it was pressed; a drag turns the view. Not *tap*: in `GLOSSARY.md` a Tap is a consumer on a line (glossary: **Press**). A plain class, not a component: a view makes it in `afterNextRender` and disposes it with itself, as a Spring component holds a plain object and closes it. Its term in `GLOSSARY.md` is **3D Stage**: the glossary holds the screen's words too.
- **three.js mostly runs without WebGL.** `Raycaster`, `Box3` and `Vector3.project` are plain maths; only `WebGLRenderer` needs a GPU, which jsdom hasn't got. So the stage takes its renderer from a factory (`makeRenderer`), and `stage.spec.ts` passes a fake one with a real `<canvas>`: presses, hits and framing are tested with real meshes. Like a `Clock` passed into a Java service so a test can stand in for it. `OrbitControls` also wants `setPointerCapture` on the canvas, which jsdom lacks; the fake canvas has one.
- **A ray through the middle of a box's face hits it twice.** A face is two triangles, and the ray runs along the diagonal they share. In a test, put the box a little off the ray (`stage.spec.ts`, `boxAhead`).
- **`Raycaster` finds a line within 1 unit by default** (`params.Line.threshold`). The belt floor set it to 1 metre explicitly: the default, so step 124 dropped it.
- **An `effect` only hears the signals its last run read.** One that returns early, before reading a signal, isn't run again when that signal changes. Read every signal first, then return (`AreaPage.drawAttachmentArrows`). Spring has no counterpart; it's like a Vue `watchEffect` or a MobX reaction.
- **A component's styles don't reach elements made in code.** Angular scopes a component's CSS by an attribute it puts on every element of its template (`_ngcontent-…`); a `<canvas>` that three.js creates and appends lacks it, so `.stage canvas { width: 100% }` never applies. Style it inline (the `Stage` constructor, `world/stage/stage.ts`). The miss only showed on a phone: an unstyled canvas shows at its pixels' size, which equals its CSS size only at a pixel ratio of 1.
- **A tab that comes and goes with `@if`.** `<ng-template appSidebarTab="levels">` inside `@if (shows3d()) { … }` (`world/arrangement/arrangement-page.html`): the directive adds its tab when Angular creates it and removes it when the `@if` destroys it (`sidebar/sidebar-tab.ts`, `DestroyRef.onDestroy`), so the Levels tab is there only while the 3D view is. In Spring terms, a bean whose lifetime is a scope, here the `@if` block.
- **A single-choice `mat-button-toggle-group` is a radio group.** Angular Material gives each toggle `role="radio"`, not `button`, and with an icon beside its label it had no accessible name: tests found it by neither `getByRole('button', { name: '3D' })` nor by its text. `aria-label="3D"` on each toggle names it (`world/arrangement/arrangement-page.html`, the Map / 3D switch).
- **A finger leaves an element as it's lifted.** After `pointerup`, a touch fires `pointerout` and `pointerleave`, which a mouse doesn't until it moves away. A label shown on a tap and closed on `pointerleave` vanishes at once; `world/arrangement/belt-floor-3d.ts` closes it on `pointerleave` only for `pointerType === 'mouse'`.
- **`ng.getComponent(element)` in a development build** gives the component behind an element, with its signals and private fields, in the browser's console or a script (step 110: picking a splitter and moving the 3D camera before a screenshot). It's gone in a production build. The nearest Java counterpart is a debugger attached to the running app.

- **No `as` in the web code** (`consistent-type-assertions`, `web/eslint.config.js`, step 126). `x as T` tells the compiler to trust you, like a Java cast that compiles whatever is in the `Object`; `{ id: 'a' } as MachineSummary` let test data miss fields the API added (step 125's `owner`). Instead: annotate (`const element: HTMLElement = fixture.nativeElement`, which works because `nativeElement` is `any`); `satisfies T` to check a value against a type and keep its own; `querySelector<HTMLButtonElement>(…)!`; `instanceof` to narrow (`object instanceof THREE.Mesh`); a function's return type for a tuple (`(f): [string, F] => [f.id, f]`). `as const` is not a type assertion and stays allowed.
- **Module augmentation** (`declare module 'leaflet' { interface Map { _animatingZoom: boolean } }`, `world/map/remove-map.ts`, `building-outline.ts`) adds members to another library's types, here Leaflet internals its typings leave out. TypeScript merges it into the library's own interface; Java has nothing like it (you'd use reflection).
- **`obj['member']` reaches a private member** in a spec (`fixture.componentInstance['shapes']`, `map-page.spec.ts`): TypeScript checks `private` on `obj.member` but lets the index form through, typed. Like Java reflection with `setAccessible`, but checked by the compiler.
- **`ng lint` lints only its `lintFilePatterns`** (`web/angular.json`). It was `src/` only, so the e2e tests and configs went unlinted; since step 126 it also takes `e2e/**/*.ts` and the root `*.ts`.
- **`npm run typecheck`** is `ngc` for the app, templates included, then `tsc` for the specs and the e2e tests, in 10 seconds. Playwright and Vitest transpile without type-checking, so before step 126 nothing checked the e2e tests' types.

## Architecture & DDD

| Term | What it is | In this project |
|---|---|---|
| **DDD (Domain-Driven Design)** | Designing software around the business domain and its language. | The whole project |
| **Ubiquitous language** | The same words in conversation, docs and code. | `GLOSSARY.md` |
| **Bounded context** | A part of the domain with its own model and language. | Catalog, Blueprint Design, Factory Network |
| **Module** | The code that implements one bounded context. | `src/Modules/*` |
| **Modular monolith** | One application, internally divided into strictly separated modules. | ADR-0002 |
| **Microservice** | A module that runs as its own separate program and talks over the network. | Maybe in M8 |
| **Value object** | An immutable object defined by its value (`Rate` 45/8). | M1 |
| **Entity** | An object with its own identity that can change over time (`ProductionStep`). | M3 |
| **Aggregate / aggregate root** | A group of objects that must stay consistent together, changed only through the root (`Blueprint`). | M3+ |
| **Invariant** | A rule that must always hold ("stack height ≥ 1"). | Business rules |
| **Domain service** | Logic that doesn't belong to one object (`SupplyLineAnalyzer`). | M5 |
| **Domain event / integration event** | A record that "something happened". Integration events cross module boundaries. | M4 (BR-F6/F7) |
| **Outbox** | A pattern that stores events in the same database transaction as the change, then sends them, so nothing is lost. | M4 |
| **ACL (Anti-Corruption Layer)** | Translation code that keeps an external format (the game's data file) out of your model. | Catalog importer, M2 |
| **ADR (Architecture Decision Record)** | A one-page document that records a decision and its reasons. | `docs/adr/` |
| **CI (Continuous Integration)** | A server (GitHub Actions) that builds and tests every change automatically. | M0 |
