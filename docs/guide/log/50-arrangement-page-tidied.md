# Step 50 · The arrangement page tidied, and lines that run on past a factory

**Goal:** a cleaner arrangement page (asked 2026-11-19). Branch: `feat/optimal-arrangement`, on top of step 49 (committed and pushed), uncommitted.

## What you asked, and what changed

- **Keep together** and **Nodes & stations weigh** are no longer set on the page. The request leaves them out (`null`), and the server uses its defaults: 2 and 0.5. Their columns are gone from the runs list too. The API still takes them, so a script can set them.
- **Supply lines** has a column of its own in the runs list: yes or no. Until now it was only mentioned after the belt metres, and only for a run with routed belts.
- **Arrange** sits in the bar above the map, next to *Draw the area / Reset*, *Keep out* and *Belt floor in 3D*. It still submits the settings form, through the form's `id` (`form="settings"`), so pressing Enter in a field still arranges. A request's error is shown in that bar too.
- **The map no longer jumps.** The progress bar appeared and disappeared above the map each time the run was asked for again, every two seconds while it was computed, and pushed the map down and back up. It now has a slot of its own, 4 px high, that stays when the bar is gone. **And it no longer blinks** (asked after): it showed only while the run was being asked for again, a moment every two seconds; now it shows the whole time the run is computed (`busy`: loading, or the run `pending`). A resource keeps its last value while it reloads, so the status stays `pending` between the requests.
- **Solver time** is a choice of three instead of a number of seconds: *Fast* 15 s, to try settings; *Balanced* 1 minute, the default and what every run so far had; *Thorough* 10 minutes, the most the server allows, for a layout to build. Picking a run shows its time as the longest of the three it reaches. The API still takes seconds (`solverTime`, `solverTimeOf` in `arrangement-model.ts`). The time limits only the placing (CP-SAT); routing the belts after it takes its own ~10 s whatever is picked.
- **Picking a factory** (in the side bar or on the map) now fades the factories that aren't related too, as it already faded the belts: a factory stays bright when it feeds one picked, by a link whether its belts were routed or not; one the picked factory feeds fades (`relatedFactories`). Its old place, the line of its move and the white lines to its linked factories are gone, and so are the white lines when pointing at a factory: too cluttered (asked 2026-11-19). *Where they stand now* still shows the old places of all factories, when switched on.
- **The same in 3D.** The factories picked on the map are picked in 3D too, and the other way round: the pop-up gets the page's `focused` signal itself. A click on a factory (its slab or its machines) picks or unpicks it; a drag of less than 4 pixels counts as a click, a longer one turns the view. What doesn't feed the factories picked fades, by the same rules as on the map (`standsOut` for belts, splitters, mergers and the existing belts outside; `relatedFactories` for factories), on top of the levels: something fades when either says so. *Unpick factories* in the panel clears them.
- **A line runs on past a factory on the floor** (asked 2026-11-19, from Modular Frames in 3D: the copper ore line went up into the factory, and the leg to Reinforced Iron Plates came down out of it). Now the leg after a factory leaves the leg into it at a **splitter** on the floor, a white diamond on the map and a white cube in 3D, as BR-S3 has it: taps are a manifold. Not only the web: the planner (`SupplyLines.Plan`) gives that leg `Off` = the leg into the factory, as an overflow has to its top-up, and the router lays it from a joint on that belt. Where the line is topped up before the factory, the splitter must come **after the priority merger**, or the factories after would miss what it brings: such a leg is laid after the top-ups onto the same belt (`Before` in `BeltRouter.Lay`), and only squares past their mergers count (`JointsOn(belt, after)`). Where a merger fell back to the factory, the line runs on from the factory, as before. Pipes alike (a pipe junction). BR-O2 says so. **A new run is needed to see it**: the runs so far were routed the old way.

### Is a minute enough?

Not provably: every run on your area so far stopped at 60 s with *Best found in time* (feasible), never *Optimal*, and runs differ by a few percent (steps 47, 48). Whether ten minutes buys more than those few percent isn't measured yet. The solver knows how far it could still be from the best (its lower bound) when it stops; storing and showing that gap per run would answer it.

## Angular / web points

| Point | Java / TypeScript |
|---|---|
| **A submit button outside its form**: `<button type="submit" form="settings">` submits the form with `id="settings"`, wherever the button stands. Plain HTML, so Angular's `(ngSubmit)` still fires. | The same in any HTML page; no framework needed. |
| **Reserve space for what comes and goes**: a fixed-height slot around an `@if` keeps the layout still. Showing and hiding the element itself changes the height of everything below it. | Like `visibility: hidden` rather than `display: none` in plain CSS. |
| **A string union as a choice**: `type SolverTime = 'fast' \| 'balanced' \| 'thorough'` with a `Record<SolverTime, number>` for the seconds. The compiler insists the record names all three. A `mat-button-toggle-group` binds to it with `[(ngModel)]` like an input. | A Java `enum` with a field (`FAST(15)`); TypeScript needs no class for it. |
| **A signal handed over, not its value**: the pop-up's data carries the page's `WritableSignal` of picks, so both read and write the one state, and the map redraws while the pop-up is open. | Like passing a shared observable (`BehaviorSubject`) rather than a snapshot; in Spring terms, a shared bean rather than a DTO. |
| **`output()`**: the 3D view tells its parent a factory was clicked with `readonly picked = output<string>()` and `this.picked.emit(id)`; the parent binds `(picked)="…"`. The view doesn't change the picks itself. | An event or callback prop in React; a listener interface in Java. |
